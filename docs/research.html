What might explain the GEMSDOE32 result?

The upstream audit records 37,654 emitted dots after pruning near mapped faults. Its note says UNSCORED and its leaderboard estimate is a projection. The user-reported result is not independently established by an organizer receipt here.

The official metric uses maximum triangular-kernel coverage at each truth pixel. Several nearby predictions may add false-positive mass without improving that maximum. Sparse placement can therefore help, but spacing alone is not a fault-discovery mechanism.

Let T and F be weighted true- and false-positive mass and N the fixed count of truth pixels. With alpha 0.2 and beta 0.8, DTI = T / (0.2T + 0.2F + 0.8N + epsilon). If removing predictions loses coverage a and removes false-positive mass b, it helps exactly when T b > a(F + 4N + 5 epsilon), for positive denominators. This is an algebraic condition, not a score estimate. Unknown test faults make a and b unknown; an identical-fold buffered holdout is required.

Catalogue-adjacent pruning can suppress mapping-location artefacts, or destroy genuine parallel faults. Reusing a full-catalogue-derived historical prediction as a holdout control would not prove leak-free recovery. Recompute the control from visible faults inside each fold.
