What this repository is

A DOE GEMS / GeoDAWN fault-prediction workbench that produces one competition-ready GeoTIFF, with every stage re-derivable from hash-pinned inputs. The lane: a logistic fault posterior over 44 competition, public-USGS and catalogue-geometry features, sharpened by an 8-orientation matched line filter and emitted as 90,568 dots on a 3 px tile grid — all through the fleet's shared, SHA-256-pinned instrument (vendor/template66/gems57).

The answer to the question that was asked

Why did h33-h33-2-b2-…-zeros report 0.2778? It was not scored. Its own audit file says "UNSCORED" and "predicted_leaderboard_dti": 0.27467. The number is a projection of a 0.2708 owner-reported base after (i) thinning to 37,654 dots at ~2.8 px spacing, (ii) deleting every dot within 2 px of the mapped catalogue, and (iii) writing zeros outside the footprint so the upload form's [0,1] check passes. That recipe is a correct reading of the official metric: with α = 0.2 and β = 0.8, a missed truth pixel costs four times a stray dot, so coverage-maximising, thinned dot fields win.

Can we beat 0.2778? Not on the evidence in this checkout. The leaderboard leader is 0.4413; ranks 1–23 are all above 0.3167. This repo's best validated value is HOLDOUT-DTI 0.12324 [0.10926, 0.13665], which is at the fleet's ceiling but says nothing directly about the live prize, because the fleet's holdout scores catalogue recovery while the prize scores expert-mapped faults that are absent from the catalogue. The same instrument gives the fleet's best reported artifact 0.0037 — proof that the two quantities are not interchangeable. See Evidence and Hypotheses.
