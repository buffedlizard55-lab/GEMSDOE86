Why did the best historical file score relatively well — and can we beat it?

The file named in the brief, h33-h33-2-b2-…-zeros, is (per its own pinned audit in GEMSDOE32) a dotted base raster with every dot within 2 px of the mapped catalogue deleted (37,654 dots). Plausible mechanism, stated as explanation not proof: under DTI (α=0.2 FP penalty, β=0.8, 300 m triangular tolerance), catalogue-adjacent dots are redundant — near a known fault they earn little new-fault credit but pay full precision cost — so pruning them raises the score without any new geology. It is metric geometry, not a discovery. Its 0.2778 (and the brief's conflicting 0.4413 / 0.3195 leaderboard highs) are owner/user-reported: no submission-page receipt exists in any repo audited here, so none is reproduced as a confirmed score. Beating it requires a surface whose new-fault placement is genuinely better — which is exactly what Gate 3 tests, and what this candidate failed. The honest answer: possible in principle, not demonstrated here, and not claimable from projections.
