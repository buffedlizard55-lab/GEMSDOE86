Why H33 may have improved—and what that does not prove

The inspected owner-side H33-2-B2 build is primarily a selection/pruning change: it removes a buffer of dots near the published fault catalogue from a prior emission. Under official DTI, a prediction can gain triangular-kernel true-positive coverage near withheld faults, while uncovered prediction mass contributes false-positive weight; the official weights are α=0.2 and β=0.8. Pruning could therefore help if the removed dots carry little marginal hidden-fault coverage but meaningful false-positive cost. Conversely, pruning can remove useful kernel support. Known catalogue pixels being masked does not automatically make neighboring pixels harmless.

This is a plausible metric mechanism, not an established explanation of a confirmed H33 organizer score. The owner's manifest labels 0.2747 a projection and says no organizer score exists for artifacts in that repository; the separate 0.2778 claim conflicts with that statement. We did not reproduce H33, and its older holdout is not a substitute for this project's required shared evaluator.

Could a future result exceed 0.2778? The official public leaderboard snapshot lists 0.4413 for xiaofanhu (**ORGANIZER-CONFIRMED public-board entry**, not a GEMSDOE86 result), so 0.2778 is not the current board ceiling. That does not show how to reproduce or beat the entry. With the current data and registry blockers, GEMSDOE86 cannot produce or validate a better TIFF in this run.

Holdout contract

Use the whole-component, buffered split

The inspected shared `holdout.py` contains more than one split. The selected function is `buffered_component_draw`, not the short-segment `build_holdout` alternative. Its code describes whole 8-connected catalogue components, label-blind quadrant selection, a boundary buffer, and a separate feature-context collar. If the exact shared evaluator entry point cannot consume this fold unchanged, stop and resolve the protocol mismatch; do not silently edit or fork the evaluator.

  • Build every catalogue-derived feature from the fold-visible fault mask only.
  • Mask the visible fault pixels exactly from scoring; preserve withheld truth.
  • Use the shared evaluator version gems57-pooled-hide-v2 and official pooled DTI: α=0.2, β=0.8, 300 m triangular kernel.
  • Record the evaluator version, actual withheld-positive pixel count, and pooled 95% CI in every reported HOLDOUT-DTI result.
  • Test each candidate feature alone. AUC above 0.90 is a leakage alarm, not a model win, until resolved.
  • Check both continuous surface and final raster against a complete, hash-verified registry; stop if rank correlation is above 0.90 or more than 70% of dots lie within 3 px of one registry raster.
