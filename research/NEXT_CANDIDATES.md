# Ranked untested hypotheses for a future authorized lane

**Review date:** 2026-10-22. **Status:** hypotheses only; none of these was run in this review, no submission slot was selected, and no score improvement is claimed.

The H86-RMRB candidate already in this repository consumed the lane's three-experiment budget and triggered the literal registry-overlap stop rule. The prompt's assigned-method paragraph was missing, so H86 was never authoritatively assigned. Do not treat this list as permission to run another lane. The rankings below are qualitative scientific priors, not numeric projections. Novelty is checked only against the current GEMSDOE86 source tree; uniqueness across the many sibling GEMSDOE sites is not established.

| Rank (qualitative expected DTI potential) | Hypothesis and exact layers | Physical signature | Why it could identify catalogue-missing faults | Named non-fault mimic / discriminant | Difference from methods in this repository | Data availability and implementation cost |
|---|---|---|---|---|---|---|
| **1 — medium–high potential; low confidence** | **Displaced magnetic-contact pair, gravity-conditioned.** Competition stack: reduced-to-pole (RTP) magnetic anomaly, total magnetic intensity (TMI), isostatic gravity anomaly. | Detect coherent magnetic contact/ridge endpoints at multiple scales; pair endpoints only when a plausible transverse offset vector and a spatially coincident gravity-gradient change support the same break. Score the inferred offset line, not the magnetic edge itself. | A concealed fault can displace an older magnetic boundary while producing little or no surface scarp. The contact is evidence of the displaced marker, not itself assumed to be a fault. | **Intrusive contacts and survey seams.** Require the paired geometry to persist across scales, have plausible continuity, and not align with flight-line boundaries; check against independent gravity. | Current `strand_orientation.py` estimates magnetic edge tangent/coherence; `geo.py` supplies magnetic/gravity gradients and curvature; neither implements paired-endpoint displacement inference. A code search found no contact-offset/phase-symmetry pair detector. | Uses competition feature families described on the official problem page; no new external data is required in principle. The shared feature cache is absent, so the layers cannot currently be validated here. **Cost: high** (multi-scale ridge extraction, endpoint matching, seam QC). No numeric DTI gain forecast. |
| **2 — medium potential; high data/alignment risk** | **Depth-decoupled MT conductance-edge migration.** USGS Great Basin conductance grids for 2–12, 12–20, 20–50, 50–90, and 90–200 km intervals; compare with competition `cond_surf`, depth-to-conductive-base, RTP/TMI. | Compare independently normalized edge positions/orientations across the shallow and deeper conductance intervals; score only coherent, physically plausible lateral edge migration with a magnetic or gravity boundary. These are depth-interval conductance integrals, not point-depth images. | A dipping or vertically segmented structure may have a systematic lateral offset with depth under cover, where a surface fault catalogue has no trace. | **Regional lithologic/basin boundaries and inversion regularization.** Require resolution/uncertainty metadata, cross-depth reproducibility, and no dependence on map-edge/interpolation artifacts. | `geo.py` has single-surface conductivity and basement-gradient features. The proposed test uses a multi-interval conductance volume and cross-depth displacement; no such depth stack is implemented here. | Official USGS ScienceBase record [10.5066/P9TWT2LU](https://www.sciencebase.gov/catalog/item/62979746d34ec53d276c113b) lists five GeoTIFF conductance layers and their depth intervals; the GDR record [1391](https://gdr.openei.org/submissions/1391) also lists MT conductance maps. This establishes a public catalog/download listing, **not** that bytes, CRS, coverage, license terms, or resolution match the competition grid; audit those before treating the idea as ready. **Cost: high.** |
| **3 — medium potential; moderate–high cost and event-selection risk** | **Raw seismicity lineaments with mechanism support.** USGS ComCat/FDSN event locations, depths, event types, review status, and moment-tensor/focal-mechanism products where available; compare to the supplied smoothed seismic-density bands and RTP/gravity. | Detect spatially compact, temporally persistent event clusters and fit local axes; use nodal-plane orientation only where a reviewed mechanism exists. Do not infer a fault from density alone. | Active blind structures can produce clustered earthquakes without a mappable surface scarp; raw hypocentres retain detail lost by broad density smoothing. | **Quarry/mining blasts, induced seismicity, and volcanic swarms.** Filter event types and review status, inspect temporal clustering and mechanism coverage, and treat absent mechanisms as missing data rather than a negative. | No raw event ingestion or event-type QC exists in the current GEMSDOE86 code tree. An upstream GEMSDOE32 note proposed this idea, but that is not evidence it was implemented or validated; it is not claimed novel across the sibling portfolio. | The official [USGS FDSN event query endpoint](https://earthquake.usgs.gov/fdsnws/event/1/query?format=geojson&starttime=2026-10-01&endtime=2026-10-02&minlatitude=38&maxlatitude=42&minlongitude=-120&maxlongitude=-116) returned a small GeoJSON response through the review browser tool, so the official endpoint is reachable through that path. The response included both earthquakes and an explosion, confirming the need for event-type filters. This does **not** prove local-shell/API access, complete temporal coverage, or focal-mechanism availability; those still require an explicit coverage audit. **Cost: moderate–high.** |
| **4 — low–medium potential; moderate cost; related to failed H86 family** | **Topography-conditioned radiometric discordance ribbon.** USGS GeoDAWN K/Th/U/total-count radiometrics plus detrended elevation, elevation slope, and curvature; RTP/TMI may be a secondary corroborator only if the authorized lane allows it. | Cross-fit a local robust radiometric expectation conditional on elevation/slope/curvature, then test whether narrow residual ribbons persist across topographic units and are not aligned with drainage or broad lithologic steps. | Alteration-related radiometric departures that cross geomorphic units may flag concealed structures without a scarp; conditioning on relief targets transport-related false signals. | **Alluvial sorting, weathering, shoreline/shoreline-terrace deposits, and lithologic contacts.** Stratify by geomorphic setting and require held-out residual persistence. | The historical H86 candidate used a global K~Th+U+TC residual boundary gated by RTP edges, not topography-conditioned cross-fitted residual ribbons. This remains the same broad radiometric-residual family, so it is not an independent lane and could be considered drift. | The official [USGS GeoDAWN release](https://www.usgs.gov/data/geodawn-airborne-magnetic-and-radiometric-surveys-northwestern-great-basin-nevada-and) lists magnetic/radiometric data, GeoTIFF products, and CC0 1.0 terms. The exact source bytes used by H86 were an owner-derived quantized mirror, not a directly retrieved USGS product. Direct product grid, coverage, and alignment are **not verified**. **Cost: moderate.** Not viable until the authorized lane and official product provenance are resolved. |

## Decision before any experiment

The highest-ranked future hypothesis has not beaten any holdout baseline because it has not been run. The project must not run it now: the H86 lane budget is consumed, the lane paragraph was absent, the template feature cache and complete registry are unavailable, and the existing TIF has a recorded literal overlap stop. No weekly submission slot is authorized. A later run needs, in order:

1. An explicit lane paragraph/selection from the competition's parallel-run protocol; do not infer it from this ranked list.
2. The actual shared feature cache with a pinned receipt (the upstream receipt currently names an ephemeral `/tmp/.../feature_stack.npy` path without a cache hash); do not substitute an ad-hoc rebuild.
3. A complete, hash-pinned registry inventory and pre-placement surface/dot gates.
4. The shared whole-segment buffered holdout and `evaluate_holdout.py` pooled spatial-cluster CI; every feature-alone canary; a current best comparable registry baseline.
5. At most three experiments/two hours; stop on a duplicate trigger or a negative comparison. Promotion to a real submission slot remains a separate selector action.
