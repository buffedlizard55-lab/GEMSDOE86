## H33-2-B2 forensic review: method, evidence, and what it does not prove

**Directly checked owner-repository evidence:** [the H33 audit JSON](https://github.com/buffedlizard55-lab/GEMSDOE32/blob/780a5a534269c79adfe6d1d7d5aadead161332aa/docs/downloads/gemsdoe32-h33-h33-2-b2-20261004T220000Z-e5eb6e7e-audit.json), [the downloadable-artifact manifest](https://github.com/buffedlizard55-lab/GEMSDOE32/blob/780a5a534269c79adfe6d1d7d5aadead161332aa/docs/downloads/submissions_manifest.json), and [the owner site's home page](https://github.com/buffedlizard55-lab/GEMSDOE32/blob/780a5a534269c79adfe6d1d7d5aadead161332aa/docs/index.html). The owner audit describes a post-processing filter: start with an earlier dotted raster and delete every prediction at catalogue distance `<= 2` grid cells. The owner's grid is 100 m per cell, so this is a 200 m exclusion distance. The resulting owner artifact is recorded as 37,654 positive cells. These are artifact properties, not an independently reproduced experiment.

**Score status:** the current owner manifest labels this file `PRIMARY`, but its receipt field is `null`; the site's note explicitly says `UNSCORED` and labels its projected leaderboard estimate as a projection. Therefore the value quoted in the user's prompt is **not verified as ORGANIZER-CONFIRMED**. It is also not admissible as HOLDOUT-DTI: the historical H33 JSON does not provide the required evaluator version, withheld-positive count, or spatial 95% confidence interval. The prompt also gives conflicting contemporary leaderboard figures; this session could not access the live DrivenData board, so no one of those figures is used as a target or score. See the [official leaderboard](https://www.drivendata.org/competitions/306/competition-doe-gems/leaderboard/) for a current manual check.

**Why the filter might help, if a submitted score later confirms a gain:** the distance-tolerant Tversky objective rewards recovered fault pixels and penalizes unsupported prediction mass. A near-catalogue dot can be a false positive when it is close to a mapped fault but not to a new target; deleting such dots may improve precision while preserving much of the new-fault coverage. This is a location-pruning mechanism, not a new geological signal. It is not automatically beneficial: faults can form splays and parallel strands close to mapped traces, and the competition's 300 m tolerance means predictions 200–300 m away can still contribute useful coverage. The sign of the effect depends on the actual hidden faults, not on the heuristic alone. A paired, buffered hide-and-recover test with all catalogue features recomputed from visible segments is needed to establish it.

**Can GEMSDOE86 credibly beat the cited result?** It is possible in principle, but there is no evidence here that it has, and no candidate can be generated responsibly in this session. There is no official receipt for the reference value, no lane paragraph, no shared cached feature stack, no complete cross-project raster registry, and no comparable current-best HOLDOUT-DTI with the required spatial interval. The old H33 internal holdout snapshot is not promoted as a score or benchmark. We did not download or copy the historical TIFF. The prior site's suggested note is recorded as 177 characters, exceeding this project's 140-character note policy; it is not reused.

A higher result cannot be promised or inferred from historical scalar values. Many submissions are transformations of shared base rasters; counting them as independent geological evidence would be pseudoreplication. No score improvement is claimed.

## Ranked candidate hypotheses — preregistration, NOT experimental results

No numeric expectation is defensible without the holdout, layer identities, and baseline. These ideas are preregistration candidates only; uniqueness against all sibling repos is **not established**. The current checkout implements none of them. All layer names need confirmation against actual band descriptions and the cached-stack manifest.

| Rank / hypothesis | Expected improvement prior | Specific proposed layers and physical signature | Why it could find an unmapped fault | Named non-fault mimic / discriminant | Difference from inspected methods; cost and viability |
|---|---|---|---|---|---|
| First: radiometric mixing-residual boundary | Highest *qualitative* prior; low confidence until data are verified | GeoDAWN K, Th, U plus RTP magnetics; spatially cross-fitted robust K~Th+U regression, transverse residual gradient and magnetic-edge persistence | Hydrothermal redistribution could produce narrow residual anomalies across a broad lithologic mixing trend without a visible surface trace | Weathering or compositional contacts; reject broad co-located Th steps and test residual/magnetic evidence separately | Residualized chemistry rather than raw radiometric consensus; moderate analysis cost, but new-data access is unverified, so NOT VIABLE now |
| Second: curvature-conditioned magnetic contact offset | Medium-high qualitative prior | RTP/TMI and gravity; local phase-symmetry ridges, displaced paired ridge endpoints, transverse gravity-gradient change | A concealed cross-fault could offset an older magnetic contact even where the contact itself is not a fault | Intrusive geometry or survey seams; require cross-scale offset consistency and exclude survey margins | Displaced-contact geometry rather than catalogue-tip continuation or generic worms; high implementation cost; cached layers unverified |

## Required single-lane experimental plan

1. Resolve the absent method paragraph and pin a complete registry inventory. Reuse the template's actual cached stack; the upstream feature receipt names an ephemeral `/tmp/gems32/work/feature_stack.npy`, not an obtainable committed cache. Do not silently substitute a rebuilt stack.
2. Freeze spatial folds, whole withheld segments, buffers, footprint and evaluator hashes. Derive all catalogue-based features and tuning targets from visible segments only. Mask visible faults pixel-exactly. Use pooled DTI with alpha=0.2, beta=0.8 and 300 m triangular tolerance via the shared evaluator.
3. Run each individual feature's AUC leakage canary. AUC above 0.90 blocks it pending investigation. Include shuffled and constant controls; discrimination is not fault discovery evidence by itself.
4. Check full-footprint surface rank correlation against EVERY pinned registry raster before placement. A correlation exceeding 0.90 or more than 70% dots within 3 pixels of any reference triggers duplicate/stop, with no “dense raster” exemptions. Undefined correlation and missing registry entries do not count as clearance. Repeat checks on final dots.
5. Compare candidate and incumbent on identical folds and pooled terms. Report HOLDOUT-DTI with evaluator version, withheld positive count, spatial cluster bootstrap 95% CI and paired difference CI. A conditional holdout CI is not a guarantee about private labels. At most three experiments or two hours; an unpromising candidate ends as a negative deliverable.
6. Use unmodified shared submission_writer.py; verify serialized values, metadata and SHA. Local validation is not organizer acceptance. A separate selector must authorize any weekly slot using the authenticated submission page's current remaining cap. No automatic portal submission is implemented.
